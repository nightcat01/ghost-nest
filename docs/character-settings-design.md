# Nanika Character Settings Design

## Purpose

캐릭터 설정 화면은 Nanika 런타임에 들어갈 캐릭터 재료를 만드는 도구다.

이 화면의 목표는 처음 보는 사용자도 캐릭터를 선택하거나 새로 만들고, 이미지 재료를 등록한 뒤, 표정, 표시 상태, 파츠, 무대 조합, 히트박스, 대사를 순서대로 만들 수 있게 하는 것이다.

캐릭터 설정은 재료의 사용처를 최종 결정하지 않는다. 사용처와 실행 흐름은 매핑 설정에서 연결한다.

## Core Model

캐릭터 설정에서 다루는 정보는 크게 세 종류다.

1. 캐릭터 자체 정보
2. 캐릭터가 보유한 재료
3. 런타임과 매핑이 참조할 수 있는 저장 결과

사용자가 화면에서 항상 구분할 수 있어야 하는 상태는 다음과 같다.

- 보유한 재료: 캐릭터에 저장되어 있지만 현재 선택되지 않은 재료
- 현재 선택한 재료: 편집 중인 대상
- 현재 사용 중인 재료: 표시 상태, 무대 조합, 히트박스처럼 다른 재료가 참조 중인 대상
- 저장될 결과: 저장 버튼을 눌렀을 때 실제로 기록될 데이터
- 런타임 적용 위치: 런타임 또는 매핑에서 어떤 키로 참조되는지

## Screen Families

캐릭터 설정 화면은 한 종류의 폼이 아니라 서로 다른 성격의 화면 묶음이다.

### Light Registration Screens

가벼운 등록 화면은 사용자가 빠르게 이름, 키, 설명, 기본 이미지, 경로를 정하는 곳이다.

- 캐릭터 만들기
- 캐릭터 이미지 경로 설정
- 베이스 이미지 등록
- 파츠 이미지 등록
- 공통 이미지 경로 확인
- 표정 등록
- 대사 카테고리 등록

이 화면들은 입력 필드와 목록이 중심이며, 큰 이미지 편집 작업판을 강제로 열지 않는다.

### Composition Screens

조합 화면은 이미 만들어진 재료를 묶어 런타임에서 사용할 상태를 만든다.

- 표시 상태 연결
- 표정과 베이스 이미지 연결
- 표시 상태에 파츠와 레이어 연결
- 무대 조합에 캐릭터 슬롯과 레이어 연결
- 히트박스에 영역과 이벤트 후보 연결

이 화면들은 "무엇을 조합하는지", "조합 결과가 어디서 쓰이는지", "저장 후 어떤 키가 생기는지"를 보여줘야 한다.

### Image Workbench Screens

이미지 편집 작업은 화면의 중심이 이미지 작업판이어야 한다.

- 크롭
- 파츠 위치와 크기 조정
- 레이어 애니메이션 조정
- 무대 조합 레이어 배치
- 히트박스 영역 드래그

이 화면들은 좌측 또는 상단에 설정 단계가 있고, 큰 작업판이 계속 보이는 구조가 적합하다. 확대, 축소, 원래 크기, 저장, 현재 선택 정보는 작업판 근처에 있어야 하며 이미지 영역을 가리면 안 된다.

## Material Groups

### Character

캐릭터는 모든 캐릭터 재료의 소유자다.

캐릭터 정보에는 다음이 포함된다.

- 캐릭터 ID
- 표시 이름
- 설명
- 기본 표정 또는 기본 표시 상태
- 캐릭터별 asset base path
- 공통 asset base path 참조

캐릭터 전환 시 이전 캐릭터의 재료, 선택 상태, 미리보기 상태가 남으면 안 된다.

### Base Image

베이스 이미지는 캐릭터의 기본 몸체 이미지다.

베이스 이미지는 파일명보다 저장 키로 참조하는 것이 우선이다. 파일 경로가 캐릭터마다 달라도 같은 키를 가진 재료라면 매핑이 안정적으로 연결될 수 있어야 한다.

### Expression

표정은 얼굴 또는 감정 상태를 나타내는 후보 재료다.

사용자에게는 "표정"으로 보여야 하며, 내부 key가 필요하면 보조 정보로만 노출한다. 표정은 단독으로 런타임을 완성하지 않고, 표시 상태나 액션에서 참조될 수 있다.

### Surface / Character State

표시 상태는 런타임에서 실제로 보여질 캐릭터 상태다.

표시 상태는 하나 이상의 재료를 연결할 수 있다.

- 베이스 이미지
- 표정
- 파츠
- 레이어 애니메이션
- 기본 대기 상태

사용자에게 "표시 상태 ID"처럼 의미가 불분명한 표현을 그대로 노출하지 않는다. 자동 ID 또는 기존 상태 선택을 우선 제공하고, 직접 입력은 고급 옵션으로 둔다.

### Parts and Layers

파츠는 눈, 입, 손, 효과처럼 베이스 이미지 위에 얹히는 이미지 재료다.

레이어는 파츠가 언제, 어디에, 어떤 크기로 보이는지 정하는 배치와 애니메이션 정보다. 파츠와 레이어는 베이스 이미지 좌표계를 기준으로 움직여야 하며, 확대/축소나 저장/리로드 뒤에도 위치가 흔들리면 안 된다.

### Stage Composition

무대 조합은 배경 이미지 하나가 아니라 캐릭터 슬롯과 여러 레이어를 가진 조합 재료다.

무대 조합에는 다음이 포함될 수 있다.

- background layer
- character slot
- prop layer
- foreground layer
- layer depth
- layer x/y/width/height
- fit/objectPosition/overflow 정책

무대 조합 설정 화면에서 보이는 결과와 런타임에서 보이는 결과는 같은 저장값을 같은 의미로 해석해야 한다. 무대 조합 화면의 preview는 런타임 결과를 예측하기 위한 기준 화면이다.

배경은 일반적으로 전체 stage 영역을 채우는 재료이며, prop은 캐릭터와 같은 scene viewport 안에서 앞뒤로 배치되는 재료다. prop이 캐릭터를 가리는 것은 depth와 role의 결과여야 하며, layout 계산이 서로 밀어내는 결과여서는 안 된다.

무대 조합 화면은 원본 캐릭터 설정의 직접 조작 흐름을 유지해야 한다.

- prop과 FX는 각각 목록, 이미지 선택, depth, x/y/width/height, 추가, 삭제 흐름을 가진다.
- prop과 FX는 작업판에서 직접 선택할 수 있어야 한다.
- 선택한 prop과 FX는 작업판에서 드래그로 이동할 수 있어야 한다.
- 선택한 prop과 FX는 작업판의 보이는 리사이즈 핸들로 크기를 조정할 수 있어야 한다.
- 작업판 직접 조작 결과는 숫자 입력값과 저장 데이터에 즉시 동기화되어야 한다.
- 숫자 입력값을 바꾸면 작업판의 선택 레이어 위치와 크기도 즉시 갱신되어야 한다.

무대 조합 화면은 재료 출처를 사용자가 구분할 수 있게 해야 한다.

- 배경과 전경은 scene asset 후보에서 고른다.
- 소품과 FX는 scene asset 또는 part asset 후보에서 고를 수 있다.
- 공통 asset과 캐릭터 전용 asset은 선택지에서 구분되어야 한다.
- 이미지 업로드 후 새로 저장된 asset이 어떤 목록에 추가되었는지 알 수 있어야 한다.

무대 조합 작업판에는 캐릭터 기준을 확인하는 기능이 있어야 한다.

- 캐릭터 슬롯은 무대 데이터의 기준 위치로 표시된다.
- 사용자는 작업판에서 기준 캐릭터 이미지를 켜거나 끌 수 있어야 한다.
- 기준 캐릭터 이미지는 저장된 기본 이미지 후보에서 선택할 수 있어야 한다.
- 캐릭터 depth를 조정해 prop/FX와의 앞뒤 관계를 확인할 수 있어야 한다.

무대 조합 화면은 depth로 인해 오해가 생길 수 있는 배치를 경고해야 한다.

- 배경이 캐릭터보다 앞에 있으면 경고한다.
- prop 또는 FX가 캐릭터보다 앞에 있고 화면 대부분을 덮으면 경고한다.
- 경고는 저장을 무조건 막기 위한 것이 아니라, 사용자가 배경/소품/FX 역할을 다시 판단하게 하는 안내다.

무대 조합의 canvas와 zoom은 다른 개념이다.

- canvas width/height 또는 aspect ratio는 저장된 무대 조합의 해석 기준이다.
- zoom 또는 preview size는 편집 편의를 위한 화면 배율이다.
- zoom을 바꿔도 저장되는 x/y/width/height 값이 바뀌면 안 된다.
- 저장 후 다시 열면 canvas/aspect ratio와 레이어 배치가 같은 의미로 복원되어야 한다.

원본 흐름을 넘는 확장 요구는 별도 계약으로 다룬다. prop이나 FX의 layer box 안에서 이미지 자체의 x/y/width/height를 따로 조정하는 기능은 원본의 기본 계약이 아니라, 현재 요구에서 추가된 inner image placement 계약이다. 이 기능을 제공하는 경우 다음을 지킨다.

- layer placement는 prop/FX 컨테이너 위치와 크기를 뜻한다.
- image placement는 컨테이너 안의 실제 이미지 위치와 크기를 뜻한다.
- layer rect와 image rect는 검증에서 별도로 비교한다.
- overflow가 visible이면 이미지가 layer box 밖으로 보일 수 있어야 한다.
- overflow가 hidden이면 runtime과 editor가 같은 기준으로 이미지를 잘라야 한다.
- 저장, 리로드, zoom 변경 후 layer placement와 image placement가 서로 섞이면 안 된다.

### Hit Area

히트박스는 클릭, 터치, hover 같은 입력을 받을 수 있는 캐릭터 영역이다.

히트박스 편집은 드래그와 리사이즈로 가능해야 한다. 확대/축소 시 히트박스 좌표와 화면 위치가 함께 확대/축소되어야 하며, 저장 후 다시 열었을 때 같은 위치에 보여야 한다.

### Dialogue

대사는 캐릭터별 텍스트 재료다.

대사는 카테고리와 문장 목록으로 관리한다. 매핑이나 액션은 특정 문장 또는 카테고리를 참조할 수 있다. 대사가 없어서 매핑 저장이 실패하는 경우, 사용자는 캐릭터 설정의 대사 화면으로 이동해 기본 샘플 대사를 만들 수 있어야 한다.

## UI Flow

캐릭터 설정의 기본 흐름은 왼쪽에서 오른쪽, 위에서 아래로 이어진다.

권장 흐름은 다음과 같다.

1. 캐릭터 선택 또는 새 캐릭터 생성
2. 캐릭터 경로와 기본 이미지 확인
3. 표정 등록
4. 표시 상태 연결
5. 파츠와 레이어 편집
6. 무대 조합 편집
7. 대사 작성
8. 히트박스 설정
9. 매핑으로 넘겨 실제 사용처 연결

모든 화면이 이 흐름을 한 페이지 안에 전부 보여줄 필요는 없다. 다만 사용자가 지금 어느 단계에 있고, 다음에 무엇을 해야 하는지는 보여야 한다.

## Editing Rules

이미지 작업판을 쓰는 화면은 다음 규칙을 따른다.

- 작업판은 가능한 크게 둔다.
- 버튼과 입력 필드가 작업 대상 이미지를 가리면 안 된다.
- 확대/축소, 원래 크기, 저장 버튼의 위치는 화면마다 일관되어야 한다.
- 제목, 도움말, 상태 텍스트가 스크롤 중 이미지 위에 떠서 작업을 방해하면 안 된다.
- 이미지가 재로딩되는 것처럼 반짝이면 안 된다.
- 선택한 레이어, 히트박스, 파츠가 저장 후 리로드되어도 같은 위치에 있어야 한다.
- 직접 조작 가능한 대상은 선택 상태, 이동 가능 상태, 리사이즈 가능 상태가 화면에서 보여야 한다.
- 직접 조작과 숫자 입력이 모두 있는 화면은 두 입력 경로가 같은 저장값을 갱신해야 한다.

## Runtime Boundary

캐릭터 설정 화면은 런타임 레이아웃을 직접 고치지 않는다.

캐릭터 설정 화면이 저장하는 것은 캐릭터 재료와 조합 데이터다. 런타임은 그 데이터를 읽어 표시한다. 런타임 표시 문제가 발견되면 다음 순서로 비교한다.

1. 저장 데이터
2. 설정 화면 preview rect
3. 런타임 scene viewport rect
4. 캐릭터 slot rect
5. layer rect
6. image rect
7. computed style

설정 화면 preview와 runtime 결과가 다르면, CSS 값을 추측으로 바꾸기 전에 저장 데이터와 rect 비교를 먼저 한다.

무대 조합 preview와 runtime을 비교할 때는 다음 값을 분리해서 본다.

- scene canvas width/height
- scene viewport rect
- character slot rect
- prop/FX layer rect
- prop/FX image rect
- layer depth/z-index
- fit
- objectPosition
- overflow
- image placement 확장이 있는 경우 inner image x/y/width/height

## Save and Reload Contract

저장 기능은 저장 성공 메시지만으로 완료되지 않는다.

완료 기준은 다음이다.

- 저장 대상이 명확하다.
- 저장 후 목록이 리로드된다.
- 리로드된 목록에서 같은 항목을 다시 선택할 수 있다.
- preview가 저장 전 의도와 같은 상태로 복원된다.
- 다른 캐릭터로 전환했다가 돌아와도 이전 선택이 잘못 섞이지 않는다.

삭제 기능은 asset 파일 자체 삭제와 매핑/조합에서 제거를 구분해야 한다.

## Anti-Patterns

다음은 캐릭터 설정 화면에서 피해야 한다.

- 재료 생성 화면과 매핑 화면을 한 화면처럼 보이게 만드는 것
- scene을 단순 이미지처럼 설명하는 것
- surface, expression, set 같은 영어 키를 설명 없이 노출하는 것
- JSON 직접 편집을 기본 사용 흐름으로 두는 것
- 저장 버튼 위치가 화면마다 달라지는 것
- 작업판보다 입력 폼이 더 큰 화면
- 확대/축소 후 레이어나 히트박스 위치가 깨지는 것
- 캐릭터 변경 후 이전 캐릭터의 재료가 남는 것
- 설정 화면 preview와 런타임 결과가 다르지만 저장 성공으로 완료 처리하는 것

## Verification Checklist

캐릭터 설정 화면 변경 후에는 최소한 다음을 확인한다.

- 캐릭터 선택과 새 캐릭터 생성
- 경로 저장과 리로드
- 베이스 이미지 preview
- 표정 생성, 수정, 삭제
- 표시 상태 저장과 기본 상태 로드
- 파츠 위치와 크기 저장, 확대/축소 후 위치 유지
- 무대 조합 prop/FX 선택, 드래그, 리사이즈, 숫자 입력 동기화
- 무대 조합 캐릭터 기준 이미지 표시와 depth 비교
- 무대 조합 canvas/aspect ratio 저장, 확대/축소 후 위치 유지
- 무대 조합 preview와 런타임 결과 비교
- 무대 조합 layer rect와 image rect 분리 비교
- 히트박스 드래그, 확대/축소, 저장, 리로드
- 대사 카테고리와 문장 저장
- 캐릭터 전환 시 데이터 격리

브라우저 검증이 불가능하면 완료가 아니라 정적 검증 상태로 보고한다.

## A2A Loopback Criteria

다음 상황에서는 추가 구현 전에 원인 비교로 돌아간다.

- 같은 UI 문제가 2회 이상 반복된다.
- 정상 동작하던 인접 화면이 깨진다.
- 설정 화면 preview와 runtime 결과가 다르다.
- CSS만 바꿨는데 결과가 계속 흔들린다.
- 저장 데이터와 화면 해석 중 어느 쪽이 맞는지 불명확하다.
- 사용자가 "처음 보는 사람이 이해하기 어렵다"고 피드백한다.

이 경우 Planner는 Worker에게 목표, 수정 허용 범위, 수정 금지 범위, target path, regression path를 다시 전달해야 한다.
